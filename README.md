# 高校后勤资产信息管理系统数据库设计

## 概述

本数据库设计用于高校后勤资产信息管理系统，包含资产管理、报修管理、采购管理等功能模块。数据库采用MySQL，支持完整的资产生命周期管理。

## 主要表结构

### 资产相关表

1. **cs_assets** - 资产管理主表
   - 记录基本资产信息：ID、名称、类型、购买日期、价值、状态
   - 资产状态：0(闲置)、1(在用)、2(维修)，以中文形式显示
   - 添加唯一约束`uk_id`确保资产ID唯一性

2. **cs_asset_details** - 资产详情表
   - 保存资产的详细信息：序列号、保修日期、维护记录等
   - 与资产主表通过asset_id关联

3. **cs_allocations** - 资产分配表
   - 记录资产分配给用户的信息
   - 包含分配日期等字段

### 报修相关表

1. **cs_repair_requests** - 报修审核表
   - 用于管理员审核维修请求
   - 状态：1(审核成功)、2(未审核)、3(审核失败)
   - 添加asset_id唯一性约束

2. **cs_repair_requests1** - 报修请求表
   - 用于用户提交维修请求
   - 状态：1(报修)、2(未报修)
   - 添加asset_id唯一性约束

### 采购相关表

1. **cs_purchase** - 采购申请表
   - 记录设备采购申请信息
   - 包含数量、预估价格、详细描述等
   - 状态：0(待审核)、1(通过)、2(拒绝)

### 字典表

1. **sys_dict_type** - 字典类型表
   - 包含报修状态、资产状态等字典类型定义

2. **sys_dict_data** - 字典数据表
   - 保存各种状态的具体值和显示标签

### 菜单表

**sys_menu** - 系统菜单表
- 定义各个功能模块的菜单项
- 包含采购管理、资产管理、报修管理等模块

## 主要修改内容

1. 调整了资产管理表结构，使资产状态能够正确显示中文标签（闲置、在用、维修）
2. 确保报修请求和报修审核表中包含asset_id字段，并设置为唯一约束
3. 添加采购管理功能相关的表结构和菜单项
4. 优化了字典表数据，确保状态显示正确

## 使用说明

1. 执行complete_database.sql脚本创建完整数据库
2. 系统部署后，可通过菜单访问各功能模块
3. 资产状态、报修状态等使用字典表进行维护，确保一致性

## 注意事项

- 确保MySQL版本为5.7或更高版本
- 执行脚本前请备份原有数据库
